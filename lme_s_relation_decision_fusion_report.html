🧠 lme_s 实验：Relation Decision 记忆融合机制

深入解析 relation_decision 方法如何通过 pairwise 五类关系分类，实现对候选记忆的去重、合并、冲突处理与答题记忆融合

📋 基准: LongMemEval-S (lme_s) 🤖 抽取模型: gemma4-26B 🏷️ 关系分类: LLM (Qwen3-max) 📅 实验日期: 2025-06-15 📊 方法: relation_decision vs add_all

📌 一、实验概况

lme_s（LongMemEval-S）是一个长程记忆评测基准，包含 500 条多轮对话问答。 本实验在相同候选记忆（gemma4-26B 抽取）的基础上，对比两种写库方法：

方法策略总体准确率记忆数量（约）
add_all 所有候选事实全量写入，不做去重/合并 51.4% ~133,000 primary
relation_decision pairwise 五类关系分类 → 桶内聚合决策 → 有向弱边写库 → LLM 融合答题记忆 46.2% ~12,400 primary + ~1,300 evidence + ~670 answer

⚠️ relation_decision 准确率略低于 add_all，但记忆总数更少（通过 EQV/NSO 去重压缩）， 且保留了关系图谱（谁蕴含谁、谁冲突谁），为后续推理提供结构化支撑。

各阶段详解

阶段 1 — 稠密检索（Dense Retrieval）

将 m_new 向量化（embedding），在已有 primary 记忆中搜索语义相似者。 参数：pairwise_sim_threshold = 0.5，related_top_k = 3。 空结果 → 直接判为 fresh_primary（等价 IND）。

阶段 2 — 关系分类（Classification）

对检索到的每个 (m_old, m_new) 对，LLM 判断其五类关系之一：

IND
Independent 独立
两条记忆互不相关，各自独立成立
EQV
Equivalent 等价
语义相同，仅表述不同
NSO
New Stronger Old
新事实比旧事实更具体/更强（旧蕴含新）
OSN
Old Stronger New
旧事实比新事实更具体/更强（新蕴含旧）
CON
Conflict 冲突
新事实与旧事实矛盾（如状态变更）

阶段 3 — LLM 复核（Verify）

对分类为非 IND 的结果，启动第二 LLM 调用进行复核，核实关系标签是否正确。 被否决的标签降级为 IND（保守策略：只用确认的关系建边）。

阶段 4 — 优先级决策（Decision）

将同一个 m_new 的所有 (m_old, label) 对放入一个桶，按优先级决策：

① CON 冲突更新
② OSN 更强主记忆
③ NSO 更弱证据
④ EQV 等价证据
⑤ IND

只要桶内存在任一 CON，就走 CON 路径；否则检查 OSN，依此类推。全部没有 → fresh_primary。

阶段 5 — 写库执行（Execute）

根据决策结果执行具体的数据库操作（详见第四节）。

阶段 6 — 答题记忆融合（Answer Memory Fusion）

当关系成立（outcome ≠ fresh_primary），用 LLM 将 m_new 与已有的「答题记忆 C」进行增量融合， 产生一条连贯的、去重后的段落文本，仅供答题检索使用。

🔄 四、五种融合策略详解

① OSN — Old Stronger New（新事实更强/更具体）

触发条件：桶内无 CON，但存在 OSN 标签的对（m_old 比 m_new 更泛化，m_new 更具体）。

写库操作：

  1. ADD m_new 为新的 primary 记忆
  2. DEMOTE 所有 OSN 旧 primary → 变为 evidence，打 ATTACH 弱边指向新 primary

答题记忆融合策略：

  • 隐藏 m_new（新 primary），取首个被降级的 old 作为 anchor
  • LLM 融合指令：优先采用新事实的具体细节，替代旧记忆中的模糊版本；不要同时保留模糊和具体两个版本
📥 旧记忆 (evidence, 将被降级): "the user plans to visit local museums in Chicago"
📥 新事实 (primary): "the user is interested in visiting the Field Museum"
⬇️ LLM 融合（OSN 模板）
✅ 融合后答题记忆: "the user plans to visit the Field Museum in Chicago."

② NSO — New Stronger Old（旧事实更强/更具体）

触发条件：桶内无 CON/OSN，但存在 NSO 标签的对（m_old 比 m_new 更具体）。

写库操作：

  1. m_new 作为 evidence 行写入，打 ATTACH 弱边挂到最长文本的 NSO old primary 下
  2. 旧 primary 保持不变

答题记忆融合策略：

  • 隐藏旧 primary（anchor），m_new 挂为证据
  • LLM 融合指令：保留已有的具体内容为主干；泛化的新事实只在提供额外信息时才加入，否则省略以免冗余
📥 旧记忆 (primary, 保持): "the user enjoys watching cooking shows like 'Nailed It!' and 'The Great British Baking Show' for relaxation."
📥 新事实 (evidence): "the user prefers food-related content and cooking shows as comfort TV."
⬇️ LLM 融合（NSO 模板）
✅ 融合后答题记忆: "the user enjoys watching cooking shows like 'Nailed It!' and 'The Great British Baking Show' for relaxation, preferring food-related content as comfort TV."

③ EQV — Equivalent（等价重复）

触发条件：桶内无 CON/OSN/NSO，但存在 EQV 标签的对（相同含义，不同措辞）。

写库操作：

  1. m_new 作为 evidence 行写入，打 EQUIV 边挂到首个检索结果（representative）下

答题记忆融合策略：

  • 隐藏旧 primary（anchor）
  • LLM 融合指令：只陈述一次，不重复；选更清晰自然的措辞；新事实不应改变事实内容
📥 旧记忆 (primary): "the user has already replaced some of their light bulbs with energy-efficient ones"
📥 新事实 (evidence): "the user has already replaced some of their bulbs with energy-efficient ones."
⬇️ LLM 融合（EQV 模板）
✅ 融合后答题记忆: "the user has already replaced some of their light bulbs with energy-efficient ones."

④ CON — Conflict（冲突 / 状态变更）

触发条件：桶内存在任何 CON 标签的对（新旧事实矛盾，如用户搬家、换工作、改偏好）。

写库操作：

  1. ADD m_new 为新的 primary 记忆
  2. 所有 CON 旧 primary 打 UPDATE 弱边指向新 primary（不物理删除）

答题记忆融合策略：

  • 隐藏 m_new（新 primary），取首个 CON old 作为 anchor
  • LLM 融合指令：保留完整历史链（"之前是 A，现在是 B"），标明当前值；绝不丢弃历史值
📥 旧记忆 (将被 UPDATE): "the user prefers to avoid overpacking based on past experiences."
📥 新事实 (primary): "the user tends to overpack clothes."
⬇️ LLM 融合（CON 模板）
✅ 融合后答题记忆: "The user previously preferred to avoid overpacking based on past experiences, but this has changed and the user now tends to overpack clothes."

⑤ IND / fresh_primary — 独立新记忆

触发条件：检索结果为空，或所有分类均为 IND，或全部非 IND 被 LLM 复核否决。

写库操作：

  1. m_new 作为新的 primary 记忆直接 ADD，无边

答题记忆融合：❌ 不触发（独立事实无需融合，直接作为 primary 可供检索）。

🗄️ 五、记忆存储结构

融合后的记忆分为三个层级存储：

角色作用参与关系判断参与答题检索
primary 原子事实，作为关系图谱的主节点 ✅ 是 ✅ 是（除非 answer_hidden）
evidence 被融合的弱侧事实，通过边连接到 primary ✅ 是 ✅ 是
answer LLM 增量融合后的答题记忆 C，仅供回答问题时检索 ❌ 否 ✅ 是

关键设计原则

  • 🔒 不物理删除：所有旧记忆保留，仅通过 role 变更和边标记关系变化
  • 🏷️ answer_hidden 标记：已被融合进 answer memory 的 primary 在答题检索时隐藏（避免重复），但仍参与后续关系判断
  • 🔗 有向弱边：EQUIV / ATTACH / UPDATE 三种边标记不同融合路径，可追溯完整融合历史
  • 📦 cluster_root 追踪：answer memory 记录其融合了哪些 primary（fused_member_ids），形成可审计的融合链路
