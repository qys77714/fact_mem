MEME Extract 阶段详解

入口：run_exp_meme.py --stages extract → 调用 src/pipeline/extract_candidates.py，从 benchmark 对话中生成候选记忆 JSON， 供后续 4-phase 灌库（run）使用。

benchmark: meme_filler32k model: gemma4-26B 三方面模板并行 granularity: 4 turns/chunk

1 入口与配置映射

run_exp_meme.py 的 stage_extract() 读取 config/meme.yaml，组装 CLI 参数后启动子进程：

run_exp_meme.py → stage_extract
python src/pipeline/extract_candidates.py \
  --benchmark meme_filler32k \
  --output MemDB/candidates/meme_filler32k_gemma4-26B_0519_as3_cas_split \
  --model gemma4-26B \
  --suffix 0519_as3_cas_split \
  --memory-granularity 4 \
  --turn-overlap 0 \
  --language en \
  --max-new-tokens 2048 \
  --chunk-concurrency 100 \
  --mem-extract-aspects-only \
  --mem-extract-extra-template 0_mem_extract_aspect_events_en.jinja \
  --mem-extract-extra-template 0_mem_extract_aspect_preferences_en.jinja \
  --mem-extract-extra-template 0_mem_extract_aspect_social_en.jinja

2 总体流程

A
加载 Benchmark 遍历所有 episode（history_name 如 pl_001），检查 extract_progress.state 中是否已完成，跳过已完成的 episode。
B
按 Session 类型分流（MEME 特有） 每个 episode 含多种 session：evidence（含 gold facts）与 filler（填充对话）。两条路径处理方式完全不同。
C
生成 Chunks evidence → 1 chunk/session（无 turn 切块）；filler → 按 granularity=4 滑动窗口切 turn 块，每块生成 observation 文本。
D
抽取候选记忆 evidence：规则拆分 gold facts（无 LLM）；filler：3 个方面模板各调一次 LLM，合并去重。
E
写入 JSON + 更新进度 每 episode 一个 {history_name}.json，原子写入；完成后追加到 extract_progress.state 的 completed 列表。

3 两条 Session 处理路径

Evidence Session

session.metadata.type == "evidence"

  • 读取 gold_facts[].fact_text
  • 调用 build_evidence_gold_chunk_fields() 规则拆分
  • 不调用 LLM
  • 输出 source: "evidence_gold_facts"

Gold Fact 拆分规则

  • gold_if_then：以 "If my/we/I" 开头的 if-then 句式，整句保留
  • gold_split：含 " — " 且后半段为条件描述 → 拆成 primary + cas_update_rules
  • plain：普通事实，无条件字段

Filler Session

默认 type 或无 type 标记

  • 按 memory_granularity=4 切 turn 窗口
  • 构造 observation 文本（含 session 头 + 对话转写）
  • 对每个 chunk 并行调用 3 个方面模板
  • 合并 candidate_memories 并精确去重

Observation 格式示例

=== Session 1 (2023/03/01 (Wed) 09:00) turns 0-3 ===
**user**: I just moved into a new apartment...
**assistant**: Congratulations! ...

4 三方面模板并行抽取

当前配置使用 --mem-extract-aspects-only：主模板（0_mem_extract_v2.jinja）不参与 LLM 调用， 仅作为 JSON 元数据字段保留。每个 filler chunk 实际调用 3 次 LLM：

Events
客观事件、时间线、状态变化
工作/居住/行动/日期
Preferences
偏好、计划、目标、意图
主观态度与评价
Social
人际关系、身份、社交语境
亲属/同事/角色标签
↓ 按模板顺序合并，strip 后精确去重（保留首次出现顺序）

单次 LLM 调用流程（_process_single_chunk）：

  1. Jinja 渲染：将 observation 嵌入模板中的 [[ observation ]]
  2. 调用 gemma4-26B，temperature=0，可选 JSON Schema 约束
  3. 解析返回 JSON → Pydantic 校验 {"memories": ["...", ...]}
  4. 第一个模板的 raw_response 保留；后续模板省略 raw 以减小体积
并发模型：episode 之间串行处理；单个 episode 内所有 (chunk × template) 组合通过 ThreadPoolExecutor(max_workers=100) 并行。LLM 调用总数 ≈ filler_chunks × 3。

6 与后续 Run 阶段的关系

Extract 产出的候选 JSON 是 Run 阶段的输入：

run_exp_meme.py --stages run
  → pipeline_meme_4phase.py
  → --candidates-dir MemDB/candidates/meme_filler32k_gemma4-26B_0519_as3_cas_split
  → 4-phase 灌库（before ingest → before Q&A → after ingest → after Q&A）

cas_update_rules / cascade_trigger_texts 等字段在 relation_decision 方法的 cascade 更新逻辑中使用（cas_update.py）， 用于检测 evidence session 中的条件变化并传播记忆更新。
